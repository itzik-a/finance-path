# Finance Path

A personal finance web app (React, built with Vite, hosted on GitHub Pages), used on a MacBook and an iPhone (installed to the Home Screen): income, expenses, investment balances, and growth projections per source and combined. See `PLAN.md` for the concepts, milestones and decisions.

## How it's built

Vite + React 19 + TypeScript. Node 22 (`.nvmrc`). On this Mac `npm start` runs `nvm use` and then the dev server; `npm run dev` alone runs the local server (also reachable from the iPhone on the same Wi-Fi); `npm run build` typechecks and builds into `dist/`.

- Routing is the URL hash: `#overview`, `#cashflow`, `#investments`, `#investments/<source id>`, `#projection`, `#projection/<source id>` (`readHash()` in `src/App.tsx`; everything after the first `/` is `sub`).
- `src/types.ts`: the whole saved state (`AppState`): `sources`, `snapshots` (balances), `txns`, `categories`, `recurring`, `loans`, `settings` (with `prime`, the prime rate's history). Amounts are in the item's own currency (`ILS` / `USD`); dates are local `YYYY-MM-DD`, months `YYYY-MM` (`src/lib/dates.ts`).
- `src/seed.ts`: starter categories and the examples (`example: true`, `updatedAt: 0`). **Never rename or reuse an id there**: devices match items by id. A starter category added later (e.g. `c-loan`, Loan payments) joins saved copies in `normalize()` (`withSeedCategories()`), at its place in the list.
- `src/state/store.ts`: state in localStorage `financePath.v1`, `useAppState()`, `update(fn)`, `replaceState()`. `src/state/actions.ts`: every change goes through here and stamps the item's `updatedAt`; deletes are soft (`deletedAt`) with an Undo toast; `live*()` helpers hide them. Editing an example drops its `example` flag (it's mine now); `removeExamples()` soft-deletes the untouched ones.
- Recurring items: `applyRecurring()` (on start, after edits) adds every due transaction up to today with the id `r_<recurring id>_<YYYY-MM>` (yearly: `_<YYYY>`), so two devices add the same ones and a deleted one stays deleted.
- Loans (`Loan`, Shpitzer): the math is `src/lib/loan.ts` (`schedule()`: each month interest = balance × rate / 12, the rest of the fixed payment comes off the balance; the payment is worked out again in the first month, when the rate changes and after a balance from a statement (`loan.balances`); amounts rounded to the agora, the last payment clears the rest). Fixed rate, or prime + margin with prime from `settings.prime` (`primeAt()`: the latest change on or before the month, the first one also covers earlier months; one history for every prime loan; the forecast assumes the latest stays). `npm run check` also runs `scripts/check-loan.ts` (closed-form Shpitzer); run it after touching the math. `applyLoans()` (called from `applyRecurring()` and after loan / prime changes) keeps each due payment from `loan.addFrom` in Cash flow as an expense `l_<loan id>_<YYYY-MM>` with `loanId` and `interest`, rewriting them when the schedule changes and removing those it no longer has; a loan payment row opens the loan's page. Net worth (`netWorth()`) is assets less what's owed (`debtsOn()`, `balanceOn()`: nothing before the month ahead of the first payment, then the principal, then the balance after the latest payment); the net worth chart draws "Net of loans" as an `overlay` line on the stacked areas. Views: `LoanList` under the sources on Investments, `#investments/loan/<id>` is `LoanPage` (`src/views/LoanPage.tsx`); sheets in `components/LoanSheet.tsx`: `LoanSheet`, `PrimeSheet`, `LoanBalanceSheet`. The 10-year projection is investments only.
- Purchases in payments (expenses only, `TxnSheet` "Payments" field, up to 120): `savePlan()` in `actions.ts` writes every payment at once, ids `p_<plan id>_<n>`, each with `plan: { id, part, parts, total }`; amounts split to the agora with the odd ones on the first (`splitAmount()`), dates the first one's day or the month's last day (`planDate()`). Editing any payment rewrites the whole purchase (fewer payments soft-delete the rest; one payment leaves a plain transaction); `deletePlan()` removes all with one Undo. Future payments count in their own months; Cash flow's month switcher goes forward to the last one.
- Views (`src/views/`): `Overview` (net worth stacked by source, this month, upcoming payments: purchases in payments and recurring expenses by next date (`upcoming()` in `finance.ts`, `nextDue()` / `dueIn()` in `actions.ts`; next month's total, the rest of this month, what's owed on purchases; a row opens the purchase or recurring item), 10-year teaser), `CashFlow` (month switcher, summary, 12-month `BarChart` that opens a month on tap, by day / by category, search across all months, links to the `RecurringSheet` and `CategoriesSheet`), `Investments` (list; `#investments/<id>` is the source page with its `SourceProjection`, balance history and `SnapshotSheet`), `Projection`. Sheets in `src/components/`: `SourceSheet`, `SnapshotSheet`, `TxnSheet` (also edits recurring items), `RecurringSheet`, `CategoriesSheet`, `DataSheet` (sync, settings, backup); `ui.tsx` (`Seg`, `Switch`, `Stepper`, `Field`, `AmountInput`, `PercentInput`, `Select`, `Sheet` + `closeSheet()`, `useSessionState`, `useLocalState`). Fields marked `data-autofocus` get focus when a sheet opens.
- Projection: the math is `project()` in `src/lib/compound.ts` (monthly: return, then the balance fee /12, then the contribution less the deposit fee; the contribution rises by `raisePct` every 12 months and stops after `contribUntil`; index 0 = now). `npm run check` tests it against hand calculations (`scripts/check-compound.ts`); run it after touching the math. `src/lib/projection.ts` `runAll()` projects every picked source with and without contributions, converts to the display currency at today's rate, optionally deflates (today's money), and adds low / high runs (return ∓ `settings.spreadPct`). Projection screen prefs are per device (localStorage `financePath.projection`).
- Charts: `src/components/TimeChart.tsx` (months on x: lines, a lone line's wash, stacked areas with a 2px surface gap, a band, dots, a Today line, crosshair tooltip with every series, arrow keys; `connect` draws across gaps; `zero={false}` fits the axis) and `BarChart.tsx` (grouped columns ≤ 24px, rounded tops). `monthTicks()` picks axis months / years. Net worth (`netWorthSeries()` in `src/lib/finance.ts`) is drawn straight between recorded balances; the tooltip says "between balances" for months without one.
- Money (`src/lib/money.ts`): `fmt()` (₪12,345, compact ₪1.2M), `convert()` at `settings.usdIls`, `parseAmount()`. The rate refreshes from the ECB daily rate (`src/lib/fx.ts`, frankfurter.dev) every 12 h while `settings.rateAuto`; setting it by hand turns auto off.
- Sync (`src/state/sync.ts`, the piano-path / workout-path / feed-path pattern, encrypted): one private gist, file `finance-path.json`, found by filename. The file is an `Envelope` (`src/lib/crypto.ts`): AES-256-GCM, key from the passphrase with PBKDF2-SHA256 (600,000 rounds, random salt stored in the envelope), fresh IV per write. Connecting is `probe(token)` (finds the gist or not) then `unlock(passphrase)` (opens it, or creates it). localStorage `financePath.gist` holds the token, gist id, salt and the derived key, never the passphrase. A file with another salt (passphrase changed on another device) or a key that fails puts the device in `locked` ("Passphrase needed"). `changePassphrase()` re-encrypts with a new salt. Merge (`src/lib/merge.ts`): every list per item by `updatedAt`, settings by `settings.updatedAt`. Writes are batched (2 s after the first change, then at most one a minute; leaving the app or Sync now sends right away); reads send the ETag (a 304 is free). Encryption needs a secure context: works on https and localhost, not on the LAN dev address.
- Backup (`src/lib/backup.ts`): always encrypted, the same `Envelope` as the gist file. On a synced device it's sealed with the sync key (`deviceKey()` in `sync.ts`; opens with the sync passphrase in use when it was made, no prompt on a device with that key); on a device that doesn't sync, the user chooses a passphrase for it (`keyForPassphrase()`, new salt), and because that derivation is slow the file is built first and saved from a second tap (`Save backup file`, so the iPhone share sheet still has its user gesture). Import: `readBackup(file, deviceKey)` opens it with this device's key when the salt matches, else returns `{ locked }` and `openLocked(env, passphrase)` asks; old plain-JSON backups still import (flagged `encrypted: false`). Import merges.
- Styling: plain CSS in `src/styles.css`, tokens in `:root` (Workout Path / Feed Path system with a green accent `#0F7B5F` / dark `#5CD3A8`). Chart series use `--s1`…`--s8` (the dataviz skill's validated categorical palette, light and dark), `--s-other` past eight. A source keeps its colour slot (`Source.color`) for life.
- **Theme**: System / Light / Dark per device (`src/lib/theme.ts`, localStorage "financePath.theme", nothing stored = System), chosen in settings (`components/ThemePicker.tsx`). It sets `<html data-theme="light|dark">`; an inline script in `index.html` does it before the first paint. Also a style per device, Classic / Bear (localStorage "financePath.style", `<html data-style="classic|bear">`, `StylePicker`): Bear redefines the surface / text tokens with Bear's greys (Knowledge Path's Graphite values, the green accent kept) and gives the sidebar its own `--side-*` tokens (dark sidebar, grey selected row; inside it `--surface`, `--surface-2`, `--raised`, `--line`, `--ink` and `--muted` are redefined so everything in it follows); the theme-color metas take the style's background. Dark tokens are `:root[data-theme="dark"]`, a dark-only rule is `:where(:root[data-theme="dark"]) .x { … }` (same specificity as `.x`). Never use `@media (prefers-color-scheme: dark)` in CSS.
- PWA: `public/manifest.webmanifest`, `public/icon.svg`, PNG icons in `public/icons/` (full-bleed, made from the SVG with `qlmanage` + `sips`), `public/sw.js` (production only; network first for the page, cache first for hashed assets; never touches other origins).

## Rules for changes

- Design mobile-first (iPhone ~390 px), tap targets at least 44 px, safe-area padding. Below 768 px: top bar + bottom tab bar (4 tabs); from 768 px a sidebar. Check both widths, light and dark.
- Colours only from the CSS tokens in `:root`; light and dark themes must both stay readable. Text never wears a series colour (use a swatch beside it).
- New state fields must be optional in `normalize()` so older copies still load.
- Nothing about the user leaves the device unencrypted: the gist and backup files only get the envelope, the rate service only gets a fixed URL. Don't add a request that sends amounts, names or notes anywhere.
- Changing the projection math: update `scripts/check-compound.ts` and run `npm run check`.
- Run `npm run build` after edits; it must pass with no type errors.
